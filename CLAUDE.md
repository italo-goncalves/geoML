# CLAUDE.md

Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

## 1. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

## 2. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

## 3. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it - don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: Every changed line should trace directly to the user's request.

## 4. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" → "Write tests for invalid inputs, then make them pass"
- "Fix the bug" → "Write a test that reproduces it, then make it pass"
- "Refactor X" → "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:
```
1. [Step] → verify: [check]
2. [Step] → verify: [check]
3. [Step] → verify: [check]
```

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

---

**These guidelines are working if:** fewer unnecessary changes in diffs, fewer rewrites due to overcomplication, and clarifying questions come before implementation rather than after mistakes.

# Communication between LLM and user within code

## Locked-code convention (MUST follow)

Some code is user-maintained and must never be modified by Claude.

- Block marker — never edit anything between these lines (not even formatting
  or imports). Reading, calling, and wrapping the code is fine:

  ```python
  # === LOCKED: <owner/reason> ===
  ...
  # === END LOCKED ===
  ```

- File marker — the whole file is user-maintained (placed at the top, after
  the module docstring):

  ```python
  # LOCKED FILE — user-maintained. Do not edit; propose changes instead.
  ```

Rules:
1. Before editing ANY file, check it for `LOCKED` markers.
2. If a locked region has a bug, or its interface doesn't fit, STOP and propose
   the change to the user (diff or description) — never apply it directly.
3. Renaming, moving, or deleting a locked file also requires asking first.
4. Unmarked code is normal — edit as usual.

## Notes-to-Claude convention

Comments starting with `# CLAUDE:` are notes addressed to Claude:

```python
# CLAUDE: this expects NHWC float32 in [0,1]; write the adapter accordingly.
# CLAUDE: is dropout=0.3 too high here? suggest, don't change.
```

Rules:
1. When the user says "check my notes" (or similar), grep the repo for
   `# CLAUDE:` and handle every hit.
2. Act on notes found while reading a file, even if not explicitly told.
3. After resolving a note, delete the comment (quote it in the reply so the
   resolution is traceable). Notes ending with `(keep)` stay in place.
4. A note inside a LOCKED region may be read and acted on, but the region
   itself still must not be edited — including removing the note; ask instead.


## Communicating changes

1. After completing a coding task, give a small summary about the files and lines changed, as well as the functions, methods created, etc.
2. Do not commit the changes immediately; allow the user the opportunity to open the IDE and see the changes.
3. When you do commit, include the user's own uncommitted changes as well —
   never stage only your own files. Describe them in the commit message as you
   would your own, reading the diff to see what they do.

# Project: geoML

Machine learning models for spatial/geoscientific data, centered on **variational Gaussian processes**. TensorFlow / TensorFlow-Probability backend, all computation in `float64`. GPL-3 (dual-licensed; see README). Since 0.6.0 the package is five subpackages plus the flat survivors (no `src/` layout): `data/` (containers, variables, meshes, blocks, drillholes, inducing helpers, Zarr io), `latent/` (the modelling paradigms), `math/`, `stats/`, `viz/`, and flat `models`, `likelihood`, `kernels`, `transform`, `warping`, `parameter`, `datasets`, `metrics`, `persistence`, `storage` — the first six pinned flat because **saved models replay their dotted paths** (`persistence._resolve` imports `geoml.likelihood.Gaussian` and friends by name). Facades re-export everything the old flat modules held, and one-line shims sit at every old path (`geoml/tftools.py`, `geoml/drillhole.py`, ...) for one release — a class recorded in a save must keep its old path importable forever.

the caller's kind kept, its invariants refusing a reduction that breaks the promise; `get_contour(..., simplify=)` applies it on the way out) and `smooth()` is Taubin — explicitly cosmetic, its docstring carrying the measured price (accuracy against the level set worsens; `supersample` is the honest route). `Solid3D` does `union`/`intersection`/`difference`, and cutting across kinds keeps the caller's kind (sheet ∩ body → sheet; body ∩ sheet → the volume below it, via extruding the sheet; sheet ∩ single-valued sheet → the piece below it, through the same extrusion — a fold refuses). `topo.clip_meshes([...])` is the batch form: one extruded ground serves every cut, bodies back closed, sheets back sheets. Bad combinations raise `NotClosedError`/`InconsistentMeshError`/`NotSingleValuedError`/`MeshTypeError`, all `ValueError` subclasses. **The booleans have one engine, and VTK is not it.** `Solid3D._combine` sends two bodies to `_resolved`, which asks the vertices whether the surfaces cross: apart or nested is answered exactly and cheaply (one body, both, or nothing), and anything crossing goes to `_implicit_combine`. **VTK's exact filter was removed in 0.6.7 because it segfaults** — not errors, *segfaults* — on contour-derived bodies, taking the session with it: measured from 836 triangles upwards, at the origin and at 1e6, on shells cleaned, de-slivered (they have none) and decimated, while a box against a box and two 1680-triangle spheres pass. A crash cannot be caught, so the error-and-empty-output fallback the filter used to sit behind never got a turn on exactly the meshes that needed it, and no measured property separates the crashing inputs, so no screen would be safe. What was given up is exactness where VTK worked. Do not reinstate it without a process boundary. `_implicit_combine` answers instead: signed distance per body on a ~2M-cell grid over the region the answer can occupy, `max`/`min`/`max(a,-b)` for intersection/union/difference, the zero surface contoured back. **The distance queries run on a pool of forked workers** (`_signed_distance`, threshold 20k points, capped at 16 workers): VTK holds the GIL through `FunctionValue`, so threads measured 1.2x where forked processes measured 7.9x on the queries and 3x on the whole boolean (8.6 s → 2.9 s at 56k-triangle shells), bit-identical, stable with CUDA live in the parent — the workers touch only VTK/numpy; platforms without fork take the serial path, and Python's fork-in-threads DeprecationWarning is deliberately suppressed at that one site with the reasoning recorded. The crossing test in `_resolved` probes ~2k vertices a side first and pays the full vertex queries only when a probe comes back one-sided, which is the only time the full answer is needed. Robust by construction, exact to the grid's step, and said out loud in a `UserWarning` naming the step. The fields are **banded** (`_banded_distance`): distance is 1-Lipschitz, so a coarse pre-pass (one sample per 4³ fine cells) settles signs away from any possible crossing without queries — zero in-band error, perfect sign agreement — and each body's band is masked by the other's coarse field so neither resolves where the other decided. Measured: 68 s of distance sweeps → under 4 s, the whole cut 72 s → 8 s, bit-identical. A decimated-proxy variant was measured (2.5× more) and rejected for trading exactness. `get_contour(close="above"|"below")` pads the cube so a contour reaching the grid edge closes into a body; `BlockSet3D.get_contour` takes the same argument, closing with ghost cells that mirror each boundary block at its own size, the cap's cells joining the fine-cutting (a cap between mismatched sizes tears like any hanging node); **the shell mirrors all 26 directions, diagonals included** — nothing crosses a box edge from inside, but the cap itself runs along the boundary, so with face ghosts alone it reached the shell's own edge and stopped there, which is why `close="below"` (whose kept region touches every face on most models) came back slit along all twelve box edges. Whatever VTK returns is passed through `math.geometry.drop_degenerate_faces` before `mesh3d` classifies it: where the level set pinches at a cell corner the marching-cubes case writes its zero-area triangles out anyway, and a sliver or a twinned face makes an edge repeat the same way round, so a surface closed and consistent everywhere it had area was coming back a bare `Mesh3D`. **The cap lands on the box face**, each ghost holding the reflection of the block it mirrors about the contour level (`2*value - v`, `_ghost_values`) so the crossing falls halfway between the two centres. One shared constant put it against the block's own centre, half a block short, which cut a grade shell back wherever it met the model edge: measured against Monte Carlo, `close="above"` read -6.3% at a face and -20.0% at a corner, and reads within 1% now, its complement within 0.2%. **The box of a block model runs from the first block's centre minus half a step** -- `BlockSet3D([0,0,0], n, 10)` spans [-5, 155], not [0, 160] -- so take it from `bounding_box` and never from the constructor arguments; an earlier version of this note reported the opposite sign because a test reference did exactly that. They read and write DXF (`from_dxf`/`export_dxf`, geometry only), and every container can be told where its locations sit relative to one (`assign_from_surface` above/below a sheet, `assign_from_solid` inside a body — both write a metadata column; blocks can also report the fraction cut). `BlockSet3D(PointData)` is the variable-size block model: every block's origin and size are whole numbers of a base cell (`step / discretization ** max_levels`), so it is built full and `split` keeps it tiling exactly (`is_full()` counts base cells — volume alone cannot tell a gap from a cancelling overlap). **`discretization` is also the refinement ratio** — a block splits into its own sub-blocks, one child each, per axis and not necessarily by two, so `[2, 2, 1]` refines in plan and leaves the bench height alone, and sub-block `j` and child `j` are the same corner (which is what lets a coarse prediction speak about the blocks a split would make). Being constant across levels is why nothing downstream changed: every block fans out into the same number of rows, so `_aggregate` still reshapes and batches need not be level-sorted. Per-block geometry is `block_size`/`block_volume`, deliberately not `step_size` (which means one size for the whole object). `split` keeps what the unsplit blocks hold (same block, same support) and leaves the children missing; `unpredicted()` names them and `predict(..., where=...)` fills only those, which is bit-identical to predicting the lot because a location's value does not depend on its batch. Metadata is inherited by children — it describes the ground — while predictions are not. **It cannot be subsetted**: `__getitem__`/`subset_region` raise, because `PointData`'s would return a plain `PointData` with no origin, level or size — a thing that looks like a block model and cannot report a tonnage. Exclude ground with `refine(..., where=mask)` — those blocks are never predicted at any pass *and* never cut, the mask being carried across each split — and hand it off through `as_data_frame` (a size per row), `as_pyvista` (hexahedra) or `to_zarr`. `predict(..., where=)` on a container that lacks the variable creates it and leaves the unnamed rows at NaN (what `unpredicted` reads); it never reallocates an existing one, which would wipe what the untouched locations hold. It exports as welded hexahedra (`as_pyvista`) and contours by **painting the welded mesh's own point field onto slab-wise regular grids and running flying edges** (`_painted_contour`: cell-equal corner means — one vote per block, whatever its size — with trilinear interiors inside coarse blocks, which is what VTK interpolates across a hexahedron and survives subdivision, so the fine lattice reproduces the coarse cell's surface; a valueless block paints its points absent, not background; measured 11.9→8.5 s at 912k blocks, the welded-hex unstructured path having spent 9 of its 12 s on `unique`-welding and VTK's single-threaded unstructured contour). This is the **one route for every field** — an earlier version painted *cell* values, whose volume-weighted interface corners pinched near-binary indicators into closed-but-inconsistent debris (46 same-way edges on the real Assen model) and needed a share-of-near-level-cells router around it; the last two pinches after the corner fix were **float32, not geometry**: every VTK image contour writes single-precision points with no say in the matter, which at mine-grid coordinates quantizes a northing of 2.8e6 to 0.25 m steps and snaps crossings onto any lattice plane the surface grazes, so the image lives in the lattice's own frame (origin zero, spacing one, float32 resolving ~1e-5 of a cell) and the world enters after the contour, in float64 — the grid path already worked this way. A `Mesh3D` classification still re-routes through the welded mesh as the last word (fired zero times on the real model); vertex snapping and collinear-face dropping were both measured worse, the latter tearing 46 902 edges open. `_resolved`'s disjoint conclusion is cheap since 0.6.7: boxes apart answer with no vertex query at all, overlapping-box disjoint pairs pay one full scan of the smaller vertex set (crossing puts vertices of *each* body on both sides of the other, so one side's scan decides), and the second scan is owed only for possible nesting — which the bounding boxes say for free. All 15 Assen rock-pair intersections run in 95 s, 14 through the implicit grid (adjacent domains overlap by thin films), one exactly disjoint (`get_contour(path, value)` — the column named by its tree path, `"metals/zn"` defaulting to the component's prediction, a bare `"zn"` accepted as sugar while unique; the column is read straight from the container by its resolved path — `as_pyvista` used to be built whole just to read one column out of it, welding every corner and exporting every variable first), values being averaged from blocks onto corners first. A hexahedron is contoured from its own eight corners, so a coarse block cannot see the corners its finer neighbours put in the middle of the shared face and the two sides tear the surface apart along it; `_cut_to_contour` therefore cuts the blocks a surface runs through down to the finest size **in the mesh handed to VTK, never in the model**, one ring of neighbours included. Nothing is predicted: a child takes its parent's value plus what the corners say about the shape across it (`_trilinear_weights`), and because those weights are symmetric the correction cancels over the children, so a block's estimate stays the mean of the children replacing it — copying the parent instead costs 0.8% of a surface's area, interpolating without the anchor drifts 1.5% in mass. Widening the *refinement* fixes the tears equally well and costs 5x the blocks, which is why it is not what happens. `supersample` cuts that mesh further levels past the model's finest block — **default 0 since 0.6.7**: its measured benefit (rounder and *closer*, worth a model 3.4x the size) is real on smooth fields and near-zero on the near-binary indicator fields real workflows contour most (908k-block model: one level cost 3.5-5.8x the time for 0.03-0.17% of volume). Pass 1 for a smooth grade at an interior cut-off; at 1 it what VTK reads between corners is trilinear, creased at every face, and averaging onto corners again at each level composes into a rounder reconstruction — so the surface both turns less sharply and sits *closer* to the true level set, matching a model 3.4x the size for no prediction. Smoothing the triangles was measured and rejected (Taubin: a sixth less faceting, 50% further from the truth) — do not add it. `needs_splitting`/`block_shares` ask each variable for its own decisions via `_Variable.split_shares` (union over variables, `split_on` to narrow) — never reach in for `divided` from outside, it is a column on a category and a dict on a grade. `unbalanced(gap=1)` is the *second* criterion: a block whose sub-blocks agree is never marked by `needs_splitting`, yet if a neighbour was cut twice over the field turns sharply nearby and the block's eight corners are too crude a guess across its span — levelling those jumps measured 3x closer to the true surface for a third more blocks, where a whole level of extra refinement bought nothing for 2.6x as many (deeper refinement widens the jumps as fast as it narrows the blocks). It searches **from the fine side** — each fine block steps one cell past its faces and names the coarse block covering that point — because asking the coarse block what lies beyond its face is not exact (a cell of its own size holds blocks that do not touch it) and painting the base lattice is the memory the model exists to avoid. `crossed_by(mesh)` is the *third*: the blocks whose sub-blocks fall on both sides of a surface or closed body, so a topography or a vein wall forces a cut before anything is predicted (it needs no model — loop it against `split`). `BlockSet3D` also carries the `assign_from_surface`/`assign_from_solid` overrides with `fraction=`, which it lacked (it is **not** decorated `@_blockdata` — it extends `PointData`, so it fell back to the centre-only version); the shared geometry is `_sub_block_shares`/`_blocks_from_surface`/`_blocks_from_solid` at module level, called by both `Blocks3D` and `BlockSet3D`. `models.refine` drives the passes with all three criteria and stops itself: the lattice's `max_levels` bounds them; `where=` takes a mask or the name of a boolean metadata column (a stored filter), and those blocks are neither predicted nor cut. `group(mask)` is `split`'s inverse — every child of a parent or none, a partial family being refused rather than averaged — and it carries what the *ungrouped* blocks hold while leaving the parents missing, since coarsening is a change of support (metadata crosses from the first child; it describes the ground). `index_data` answers with **which block**, not a cell index per axis as a grid does, and `aggregate_numeric`/`_categorical`/`_binary` are built on it. `RotatedBlockSet3D` turns the whole thing: the lattice stays in the unrotated frame (exactness lives there) and coordinates rotate on the way out (`_centres`, `get_batched_coordinates`, `_hex_mesh`) and un-rotate on the way in (`index_data`); every mesh test reads sub-block positions through `get_batched_coordinates`, so assignments and `crossed_by` need nothing overridden. Every grid and block class has `from_data(data, step, margin, decimals)` — covers any spatial object's box (drillholes included, via their desurveyed cloud), flooring the corner to `decimals` and, on the rotated classes, rounding the fitted angles *before* the box is measured. One `aggregate(data)` replaced the nine per-class aggregators: continuous averages, categorical keeps the dominant label with **ties empty**, compositions are re-closed, metadata follows the same rule; it runs on `index_data`, whose rotated version applied the forward map instead of the inverse until this was built on top of it. Design and measurements in `docs/variable-block-models.md`. Largest module (~4500 lines). |

Both overlap neighbouring experts, so a prediction shows no seam where one gives way to the next. `grid_experts` extends regular blocks by one step, keeping every expert the same size with the Moore neighbourhood (8 in 2D, 26 in 3D) known in advance; `experts` is the unordered version — it clusters the points it is handed, then has each cluster borrow a further `overlap` of its own count from the nearest points (Mahalanobis) belonging to others. | `likelihood.py` | Likelihoods (`Gaussian`, `MultivariateGaussian`, `Bernoulli`, `CategoricalGaussianIndicator`, `GradientIndicator`, …). Holds no reference to a data container — pure tensors. Three reductions over a block's sub-blocks: `_aggregate` (mean — 25 call sites, so leave its signature alone), `_dispersion` (variance) and the pair `_proportions`/`_divided`. All read the one field `predict` builds, in the variable's own units, so a block value and everything said about its interior agree. **The noise is integrated out, never drawn**: `integrated_backward` reports `E[g(z + eps)]`, the value left once the measurement error and the sub-resolution variability are averaged over, at every support including a point — there is nothing random in it, no seed, and no dependence on the batching, and the back-transform runs once rather than twice. **There is no scalar/multivariate split**: one `_ContinuousLikelihood` serves any size — `size` is the warping's — and everywhere the old pair differed is decided by `warping.elementwise`: `_noise_nodes` returns eight Gauss-Hermite nodes when it holds and 64 seeded-scramble Sobol points when it does not (the node counts were measured on the Macpass assays — see the 0.5.8 changelog; the delta method was removed for leaving exactly the error of not correcting at all), `log_lik` takes quadrature over the latent marginals when it holds and Monte Carlo over the latent samples when it does not (there is no `use_monte_carlo` flag any more), and partial missing is allowed exactly when it holds (a mix spreads the hole over every warped column and returns one log-derivative per row). The `Multivariate*` twins are thin subclasses that only size the default warping — `MultivariateLaplace` keeps its historical `rate` name and `MultivariateHuber` its 0.1 init so old saves load. Non-Gaussian noise needs no special case — the nodes are in the unit cube and reach the noise through `_make_distribution(...).quantile`, which is how it was ever drawn. `integrated_backward` returns **two** moments: the value, and `noise_variance` — the second moment off the same nodes, so free — which is how far a *measurement* of that value would fall from it. Three variances, three questions: `latent_variance` (how sure the model is), `dispersion` (how much the ground varies inside a block), `noise_variance` (how much a sample of it would scatter). Anything comparing a prediction with an assay needs the measurement distribution rather than the stored one — `measurement_samples` keeps the nodes instead of averaging them, on **equal-share** nodes (a rule built to make an integral exact is a poor picture of a distribution), and `models.predict_measurements` is the way in, skipping any likelihood whose `warped` is False (a categorical one has no value for a sample to scatter around — ask the flag, never `getattr(lik, "warping")`). Widening the stored simulations by `noise_variance` instead was measured and rejected: right width, wrong shape. `Mixture(warping, n_components=2, family="gaussian", separation=3.0)` is the noise as **several scales of one family** sharing the latent location — the classic pair a narrow genuine one and a wide one for bad readings, which one nugget cannot tell apart and a heavy tail cannot *name*. One family is deliberate (a Student's t is itself a scale mixture of Gaussians, so mixing families is an unidentifiable reparameterization, and shape belongs to the warping); `Gamma` is refused, its spread being tied to its mean. The components are **separated at construction** — each family declares `_WIDTH_PARAMETERS`, the exponent by which each parameter carries the width (`noise` is a variance → 2, `c_rate` is a rate → −1, `df` is shape → absent), and bounds move with the value so a ceiling meant for one noise cannot clamp the wide component back; symmetric components never pull apart, which is why this is construction rather than advice. **The mixture is over the row**: the columns' densities are multiplied before the components are weighted (a measurement wrong in one component of a vector variable is a wrong measurement), so `responsibilities` is one answer per location and, since that density does not factorize, a vector mixture takes its latent expectation over the joint samples rather than per-column quadrature (`_column_quadrature`; scalar mixtures keep Gauss-Hermite). **Contamination is declared, not assumed** (`contamination=[False]*k` by default): marking a component says its readings replace a measurement rather than report one, and only then does `integrated_backward` leave it out of the value. `_noise_values` returns the nodes with **two weightings** — genuine-renormalized for the value, the mixture's own for the spread — and the second moment is about the *reported* value (`E[(y − prediction)²]`, what a residual is measured from), which collapses to the ordinary `second − mean²` wherever the two agree. Training and `measurement_samples` always keep the full mixture. The warping should be led by `ZScore(size, robust=True)`. `models.VGPNetwork.responsibilities(data)` is the way in from a container; it writes `assay/responsibilities/k` and is honest only out of fold. `_proportions` is the share of a block below a cut-off (the recoverable share); `_divided` is how often the cut-off passes through it, judging each realization separately — **only the second licenses a split**, since realizations either side of a cut-off are the model not knowing, which cutting cannot mend. A category's cut-off is zero on `ind_skew` (its log-odds against its best rival), so a contact is that zero level set and one reduction serves both kinds. `_CategoricalLikelihood._resolve` computes entropy/indicators from the sub-blocks and aggregates afterwards; `ind_skew` is two row maxima (the best, and the best with the winners dropped) rather than a mask per category — and **not** `tf.math.top_k`, which costs a flat ~19 ms a call on this GPU whatever its shape, dtype or `k`, several times the loop it would have replaced. |
| `kernels.py` | Kernels + `Covariance` objects. The **directional covariances** (`covariance_matrix_d1`, `covariance_matrix_d2`, `point_variance_d2` — what directional data are built on) are exact since 0.6.6, and the shape of the answer is why they are written the way they are. Differentiating the covariance *matrix* cannot work: it goes through a Euclidean distance, `|h|` is not twice differentiable at zero, and `self_covariance_matrix_d2` asks for a point against itself on every diagonal, so forward mode returns NaN there. So `Covariance` differentiates the **kernel** — `kernelize` is elementwise, two nested `GradientTape`s give `f'(r)` and `f''(r)` exactly — and carries the spatial part by the chain rule: `dK/dy.u = -phi A`, `d2K/dx dy = -(psi A B + phi C)` with `phi = f'(r)/r`, `psi = (f''(r) - phi)/r**2`, both with removable singularities the code takes analytically (`phi(0) = f''(0)`; A and B vanish at coincidence). Distances are measured about a common origin and squared distances below the rounding of their own expression are read as zero, which is what makes a point against itself exact rather than a distance at rounding level. Directions reach the kernel through the transform's Jacobian, by a single `ForwardAccumulator` — never *nested* ones, which crash: `math.tf.pairwise_dist` is a `tf.function` with a shape-polymorphic signature and TF's forward-over-forward machinery reuses one shape's graph for another. The base class keeps a generic forward-mode version for covariances with no distance in them (`Linear`, whose old finite differences were plainly wrong — they measured the step about a shifted origin, which only cancels for a stationary covariance); `Scale` delegates rather than inheriting it. `_NodeCovariance` delegates componentwise, which is the derivative of its operation only where that operation is **linear** — right for `Sum`, and why `Product` overrides all three with the product rule (it was returning the product of the derivatives, measured 98% wrong). The rule needs the derivative in the *first* argument, which is not in the interface and need not be: a covariance is symmetric, so `dK/dx = transpose(covariance_matrix_d1(y, x, dir_x))` — the identity that already assembles the mixed blocks in `full_directional_covariance_d1` and `GradientConstrainedInput.refresh`. `Exponential` and `Spherical` have no derivative process at all (a kink at the origin), and their `epsilon` is what the number reported for one comes from. |

| `warping.py` | Output warpings (`ZScore`, `Spline`, `Softplus`, `PCA`, `ContinuousNormalizingFlow`, …). Each declares `_mixes` — whether one component of its input can reach another of its output — and `elementwise` reads it (`size_out == 1` short-circuits: a 1×1 rotation is a sign). `ChainedWarping` takes `all(...)`, one mixing link being enough to spread a component over the others. It is what decides how the likelihood noise is integrated, so it must be truthful: `test_noise_integration.py` checks every declaration against a numerical Jacobian. Claiming to mix when you do not merely costs nodes; the reverse integrates the wrong thing. The same file checks the *other* thing `forward` returns — `log|det J|`, which composes by addition along a chain — for twelve warpings; since 0.6.5 the four that used to report zero say what they are worth (`-0.5*sum(log eigvals)` for the PCAs, `-sum(log scale)` for `ScaledSimplex`, `-log(n) - sum(log x)` for `CenteredLogRatio`, whose Jacobian is *singular* between n-column arrays and whose number is the volume factor onto the sum-to-zero hyperplane — the same in every orthonormal basis of it, which is why no balance matrix is needed). A projection (`PCA` with fewer components) keeps zero: there is no determinant to report. `ZScore(size, robust=True)` initializes from a winsorized copy of the data ([1%, 99%] fences, `_ROBUST_QUANTILES`) so a gross outlier cannot set the scale — built for the warping under a `Mixture`, and identical to the plain fit on clean data. **`initialize(x)` is a data-dependent *start*, not a fit** — `ChainedWarping.initialize` threads the data link by link, so each link sees it as it arrives, and `Rotation` (FastICA) and `Spline` (since 0.6.6, the marginal normal-score transform at its knots) both say so in as many words. `Spline`'s knots have fixed inputs on a regular [-5, 5] grid and trainable outputs carried by two compositional parameters, which pins the map at `(-5,-5)`, `(0,0)`, `(5,5)` and makes it monotone whatever they hold; the initializer sets the shape between the anchors and each arm is rescaled to reach them, which is the one approximation. **The outermost segment of each arm keeps `_OUTERMOST_SHARE` (0.2) of a uniform share and the interior ones are free to collapse** — the knots span [-5,5] and data never fills it, so every knot past the sample reads the same empirical quantile and asks to sit on its neighbour; a flat *forward* segment is a vertical inverse, and only the outermost one is extrapolated along (`backward` locates its bracket first and clips into it, so an interior flat segment costs accuracy over one interval and cannot leave it). At the absolute 1e-6 floor this replaced, a Jura latent draw came back at 1e5 and the chain's `Log.backward` exponentiated it to infinity. It was the identity before, which is why stacking `Rotation → Spline` pairs used to rotate repeatedly with nothing gaussianizing in between — measured to leave the data *more* non-Gaussian than it started (projection index 47 → 111). With it, the chain initializes as a projection-pursuit sweep. Measured on Jura, **that is where the benefit stops**: one initialized marginal transform gives the best held-out rmse and CRPS in the ladder, a single rotation sweep is worse, and two or more blow the back-transform up (56 and 189 non-finite predictions of 700) because a chain of splines is steep in the tails and `Log.backward` exponentiates it. **`Spline.backward` solves rather than approximates** (0.6.6): interpolating the swapped knots is not an inverse — the inverse of a cubic is not a cubic — and `forward(backward(y))` used to come back 1.3e-1 from `y`, so the model inverted a different map from the one it fitted. `MonotonicCubicSpline.invert` does Newton on the forward polynomial, locating the bracket once in `y` (a monotone map puts the answer in the interval the query occupies among the y-knots) and iterating on monomial coefficients, so twelve steps cost less than three did naively; round trip 1e-11 both ways at 2.6x a forward pass, with the implicit `1/f'` as its derivative. **The floor is the transform's own conditioning, not the solver's** — half a normal-score fit's intervals are nearly flat, and where `forward` compresses by `s` a machine-precision residual returns magnified by `1/s`, which is the measured 5e-11. Twelve is the default because a sweep over six samples and five knot counts showed the error stops falling there (1e-3 at three, 1e-7 at eight); a single sample had suggested three. |
| `math/interpolate.py` | Cubic-convolution and cubic-spline interpolators (TF). `MonotonicCubicSpline` (Steffen 1990) is what `warping.Spline` is built on, and since 0.6.6 it also `invert`s — Newton on the forward polynomial, which is the only honest inverse (see the warping row). **Its guards are multiplicative, not additive**: `_safe_width` replaces a zero interval width and leaves every other alone, where the old `w + 1e-6` shifted all of them — 8e-6 relative at a knot spacing of 0.125, a floor under the spline's own self-consistency and enough to stall the inversion. ## Core architecture

- **Everything trainable subclasses `parameter.Parametric`.** It holds a `parameters` dict and a flat `_all_parameters` list. Composite objects call `self._register(child)` to bubble a child's parameters up, and `self._add_parameter(name, RealParameter(...))` for their own. Training reads `get_unfixed_variables()` and optimizes with Adam — all training is gradient-based.
- **`RealParameter` wraps a `tf.Variable`** with a transform + min/max bounds, kept in bounds via `refresh()`. Subclasses encode constraints via the transform: `PositiveParameter` (log), `CompositionalParameter` (softmax/logit), `CircularParameter`, `OrthonormalMatrix`, etc. Persistence is `save_state`/`load_state` (pickle of parameter values).
- **`VGPNetwork` is the heart of the package:** `VGPNetwork(data, variables, likelihoods, latent_network, ...)`. You compose a network from `latent` nodes, attach a `likelihood` per variable, and optionally `warping`. Prefer it over the legacy `GP` for new work.
- **`predict_raw` is a dispatcher, `_predict_raw` is the body** (`VGPNetwork`, inherited by `ProjectedVGP`). `jit_compile` is settled when a `tf.function` is built, and the simulation draws are baked into the graph, so honouring `GPOptions(jit_predict=...)` and `GPOptions(qmc_simulations=...)` means holding one traced function per `(jit, qmc, expert_propagation)` combination in `self._compiled` rather than a flag on a single one; jit off uses `jit_compile=None`, which is exactly the old behaviour, and the `simulation_rule` context wraps the *call* rather than the trace because a retrace (new batch shape, new `n_sim`) can happen on any call. Keeping the public name on the dispatcher is what lets `predict` still call `self.predict_raw` (a test replaces it with a spy). The other models' `predict_raw` (`GP`, `StructuralField`) are unrelated methods and still plainly decorated. XLA is worth 3–5×, is prediction-only (on training it was slower *and* went NaN), and is off by default because it raises rather than falling back on anything it cannot compile.

## Conventions

- **Imports:** sibling modules are imported with underscore aliases — `import geoml.parameter as _gpr`, `import geoml.tftools as _tftools`. Third-party too: `import numpy as _np`, `import tensorflow as _tf`, `import tensorflow_probability as _tfp`. Match this in any module code. (Test scripts use a bare `import geoml`.)
- Every source file carries the GPL-3 header block — keep it on new files.
- **The public surface is curated, and old paths are promises.** `geoml/__init__.py`'s `__all__` names the thirteen user-facing modules; internals (`parameter`, `persistence`, `storage`) and the 0.6.0 deprecation shims stay importable but unadvertised, and the everyday names (`PointData`, the grids, `BlockSet3D`, `DrillholeData`, `VGPNetwork`, `set_seed`) are aliased at the root. Kernels/likelihoods/warpings stay module-qualified — `Gaussian` alone names three things. When moving any class, remember `persistence._resolve` replays dotted paths out of saved models: keep the old path importable (facade re-export or shim) forever, not just politely.
- **The container tree is addressed by path, and everything that reads it whole is a fold over one traversal.** `container.get("assay/Zn/noise_variance")` is the column, `values(path)` the array, `select("**/prediction")` a set, `tree()` the picture, `_metadata/HOLEID` a metadata column, `assay/Zn/simulations/7` one realization (read by indexing the store, never materializing it). A node declares what it holds — `_ZARR_ATTRS` (scalar columns), `_DICT_FAMILIES` (columns keyed by a number: a cut-off for the shares, a component's position for `responsibilities`), `_NODE_ATTRS` (facts a rebuild must carry: `cutoffs`) — and `walk`/`leaves`/`_export_leaves` drive the data frame, the pyvista fills, subsetting (`_subset_into`), carrying (`_carry_into`, `_copy_attrs_into`), `set_coordinates`, persistence and the repr off those declarations. **Add a column or family to the declarations and every consumer has it; hand-write a list in one consumer and you have re-created the bug family this replaced** (eight bugs: `update` ×2, `__getitem__` ×2, `as_data_frame`, `carry_to`/`from_variable` cut-offs ×3). One spelling per style via `render(path, style)`: `path` internally and in Zarr, `flat` (`assay_Zn_prediction`) in frames, `pretty` (`assay - Zn - prediction`) in pyvista; none of the rendered forms parses back — anything reading an export gets the mapping from `field_data["geoml_paths"]`, never from splitting a name. Design, prior art and the executed plan: `docs/variable-paths.md`.
- **Components are still four classes, and `update` is still per-class.** `VectorVariable`'s parts are plain `ContinuousVariable`, a composition's are `_Component` (reads `prediction`, not `average_sim`), a categorical's are `_Category`; a column a prediction writes passes through each `update` by hand, so test all four — `test_plots.py`'s `trained` and `trained_composition` fixtures are the pair for the graded ones. `RockTypeVariable.__getitem__` keeps its hand-written override deliberately: dropping absent categories and recoding `predicted` is semantics, not duplication.
- **Annotations are for the public interface; docstrings are for the user.** Signatures on the user-facing surface (`models`, the container methods, `drillhole`, every user-facing constructor, `metrics`, the `plots` figures, `storage`'s public methods) carry PEP 484 annotations, with the shared aliases in `geoml/_types.py` (`Where`, `Cutoffs`, `Bins`, `PathLike`, `FloatArray`) and geoML classes annotated directly in the module that already imports them. **The tensor internals are deliberately unannotated** — `tf.Tensor` in and out says nothing about the rank, dtype or axis order that actually goes wrong, and tensorflow-probability ships no stubs; `typings/tensorflow/__init__.pyi` declares TensorFlow untyped on purpose so the checker reports on the layer it can verify. `pyright` runs in CI over the file list in `[tool.pyright]`, which since 0.6.5 holds **every user-facing module** — the thirteen in `geoml.__all__` and everything under them, twenty-seven files, clean. The exceptions are deliberate and named above: `latent/network.py` and the likelihood/kernel tensor maths. **A module that is annotated but missing from that list is the worst case** — read by the editor, checked by nobody — which is exactly how the three `plots` modules drifted for a release after being annotated without being added. **A class-level declaration is worth more than any single signature** — `_SpatialData._n_data: int` closed nineteen diagnostics at once and `_Variable._Attribute` forty-five, because each fixes every call site downstream rather than one. Two rules learned the hard way: a *wrong* annotation is worse than none (`labels` is not `Sequence[str]` — the constructors accept `None`; `padded_range`/`color_limits`/`cells` return more shapes than the obvious one), and an argument that gets rebound to a different type inside its own function has no statable signature — convert into a differently named local instead (`grids.step_vector`, `prepare.continuous_parts`, `_Variable._sim_store()`). **Docstrings are technical, scikit-learn style**: summary, description, `Parameters` (description only — the annotation carries the type), `Returns`, `Raises`, `See Also`, a brief `Notes`, `References`, `Examples`. Design notes, measured comparisons and the history of what the code used to do belong in a code comment, the changelog or a design record under `docs/` — never in a tooltip.
- **Do not reach into a variable for an attribute whose type depends on the class.** (Kept as a caution, though the two examples below were unified in the code: `divided` and `proportions` are dicts on every class that has them, and `split_shares()` now differs only in how it *names* each decision.) `divided` is one column on `_Category` and a dict keyed by cut-off on `ContinuousVariable`; `proportion`/`proportions` likewise. Ask the variable — `split_shares()` is the pattern — rather than `getattr`-ing and hoping.

## Build / test / gotchas

- Install is `pip install -e .` from `pyproject.toml` (PEP 621, setuptools backend; subpackages auto-discovered — `setup.py` is gone since 0.6.0). - **RUN ONLY THE TEST FILES THAT COVER WHAT YOU CHANGED.** Not the whole suite. The full run is **~7 minutes**, most of it training real models in `test_real_cases.py` and `test_vgp.py`, and firing it after every edit burns the session on work already done. A full run has **two occasions and no others: a release, and the last piece of a change that reaches every container** — the *last* piece, not each one along the way. So a change touching every container gets one full run, at the end, after the targeted files pass. **More than one or two full runs in a working session means it is being used as a substitute for thinking about what the change can reach.** When in doubt run the files you touched and say plainly which ones you did not run; that is more useful than a green wall that took seven minutes to print. Note: a model is reproducible from `geoml.set_seed()` alone, called *before* the objects are constructed — parameter init draws from the package RNG in `stats/random.py`, and since 0.6.2 the options draw `options.seed` (training + simulations) from the same generator at construction, so there is no second knob to forget; `GPOptions(seed=...)` is a `TypeError` now, and a saved model keeps the seed it drew.
- **The documentation site** is Sphinx + MyST in `docs/source`, built with `-W` by `.github/workflows/docs.yml` and published to Pages on a tag. Three parts: the **manual** (copied in from `docs/manual/` by a `builder-inited` hook in `conf.py`, so its relative figure links keep working — the copy is gitignored, and `docs/manual/` stays the one place chapters are written and run), the **reference** (one page per public module, grouped as the module map groups them), and **internals** (the design records, by MyST `include`, single-copy). Two things the build needs and would otherwise fail on: the duplicate-object warning is filtered in `conf.py`, because several classes here share one function object on purpose (`_blockdata`, a few latent nodes) and autodoc reads that as documenting the same thing twice; and `stats.md` excludes the distribution methods TFP's base class copies into every subclass, whose docstrings are TFP's and not ours. **A code example in a docstring needs `.. code-block:: python`** — an indented block on its own is read as a definition list and fails the build.
- **Version:** **five** files say it, and they all say `0.6.5`, the last released version — `geoml/__init__.py`, `pyproject.toml`, `docs/source/conf.py`, and since 0.6.4 the plugin's `plugins/geoml/.claude-plugin/plugin.json` (its `version` field, which is what decides whether an installed plugin sees an update) and the **Version:** line in `plugins/geoml/skills/geo-ml/SKILL.md`. The changelog's top section is the work in progress, and the version is bumped at release. They drift apart easily — `conf.py` sat at `0.3.5` through several releases, and this very note sat at `0.6.1` for three — so bump all five together.
